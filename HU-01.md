# HU-01 - Token firmado con expiracion y claims minimos

## Estado de aprobacion
**Aprobado por el usuario el 2026-10-20.** Los requisitos y las decisiones tecnicas de token registradas abajo estan aprobados para implementacion.

## Veredicto
**Aprobada para implementación.** Las decisiones técnicas acordadas están registradas en este documento.

## Contexto
El servicio de autenticacion expone `POST /auth/login` y devuelve `token`, `expiresIn` y `user`. La implementacion actual codifica claims con Base64 y un secreto constante; no genera un JWT firmado. El frontend envia `client: angular-workshop`.

## Decisiones aprobadas
- Usar JWT firmado con HS256 mediante bibliotecas JWT compatibles en Java y Python.
- Requerir `AUTH_TOKEN_SECRET` en todos los entornos, sin secreto predeterminado; el secreto debe tener al menos 32 bytes UTF-8.
- Aceptar unicamente `client=angular-workshop`; rechazar el campo ausente o cualquier otro valor con `400`.
- Usar una tolerancia de 5 segundos al comprobar la coherencia entre `expiresIn` y `exp - now`; los tokens se consideran expirados en `exp` sin periodo adicional.
- Rechazar inmediatamente el formato Base64 anterior, sin validacion dual.

## Requisitos
- Exigir los claims `sub`, `client`, `iat` y `exp`.
- Obtener `client` desde la solicitud, validarlo y reflejarlo en el token.
- Comprobar que `expiresIn` coincide con `exp - now` usando una tolerancia documentada.
- No proporcionar secreto predeterminado en ningun entorno y documentar `AUTH_TOKEN_SECRET`.
- Evitar logs del token y del secreto.
- Rechazar tokens expirados, malformados, alterados y tokens Base64 previos.

## Criterios de aceptacion
- Un token valido contiene `sub`, `client`, `iat` y `exp`.
- El token se firma con HS256; Java lo emite y Python valida su firma y claims con bibliotecas JWT.
- `client` se obtiene del request y solo se acepta cuando vale `angular-workshop`.
- `expiresIn` es coherente con `exp - now` dentro de 5 segundos.
- La aplicacion falla al iniciar si `AUTH_TOKEN_SECRET` falta o tiene menos de 32 bytes UTF-8.
- Login valido, credenciales invalidas y token expirado tienen pruebas.
- No se registran tokens, secretos ni valores sensibles.
- El token Base64 anterior se rechaza al desplegar emisor y consumidor coordinados.
